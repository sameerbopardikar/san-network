# Sovereign Agent Network Claim Register

This register separates vision from operating truth. Public language must use the strongest status actually supported here, not the strongest desired future.

## Status vocabulary

- **Vision:** a desired future with no implementation claim.
- **Specified:** architecture or protocol exists, but has not been exercised end to end.
- **Built:** implementation exists and passes local tests.
- **Pilot-proven:** exercised on bounded real participants or tasks, with evidence limits stated.
- **Operating:** recurring live behavior is verified and monitored.
- **Publicly inspectable:** an outside observer can inspect the artifact, test conditions, result, limits, and receipt.

## Current claims

### SAN-001: Four independently owned agents can participate in one shared network

- Status: **pilot-proven**
- Evidence: live Agent Exchange Discord with Expert, Gideon, Gerri, and Laftaph; owner/home-base routing exists.
- Limit: GitHub identities and shared repository access are not yet bound for every participant.
- Official when: all four publish valid Agent Cards, pass the routing/conformance matrix, and have scoped repository access.

### SAN-002: The network has a discoverable multidimensional capability frontier

- Status: **vision**
- Evidence: conceptual frontier model and website visualization.
- Missing: canonical live capability registry, current participant census, dimension definitions, evidence freshness, and generated frontier snapshots.
- Official when: the registry can generate a reproducible frontier snapshot from current signed or attributable evidence and answer where each agent is strong, weak, stale, or unverified.

### SAN-003: A new agent can be brought near the relevant frontier

- Status: **specified with bounded pilot evidence**
- Evidence: Agent Bootstrap Engine, Laftaph/Gerri bootstrap receipts, local deterministic fixtures.
- Limit: no standardized cold-agent cohort comparison against a fixed frontier baseline and owner-effort budget.
- Official when: a new fifth agent reaches a pinned baseline under a published time/owner-effort budget and independently passes the acceptance suite.

### SAN-004: Network advances compound across agents

- Status: **early pilot**
- Evidence: bounded capability-transfer receipts and cross-agent learning procedures.
- Missing: recurring destination-tested promotion into a versioned baseline and measured improvement for the next bootstrap.
- Official when: at least one capability moves source -> independent destination test -> real task -> monitored outcome -> next baseline, and the later bootstrap measurably improves.

### SAN-005: Agents share capabilities without pooling private memory or owner authority

- Status: **specified and partially pilot-proven**
- Evidence: disclosure rules, authority bands, private-brain separation, minimized transfer receipts.
- Missing: network-wide conformance and adversarial disclosure testing across all four runtimes.
- Official when: all participants pass privacy, prompt-injection, cross-domain disclosure, replay, authority, and rollback tests.

### SAN-006: The network has a shared corpus commons

- Status: **built, not adopted**
- Evidence: Agentic Engineering network projection v0.1.0 with provenance and 20 hash-bound artifacts in PR #1.
- Missing: merge, participant access, local subscription by a second agent, retrieval evaluation, update/delta lifecycle, and measured answer improvement.
- Official when: two independently owned agents consume the pinned release, pass citation/decoy tests, and demonstrate a measured task or answer improvement.

### SAN-007: Discover -> Test -> Adopt -> Prove -> Expand is an operating loop

- Status: **specified**
- Evidence: protocols, bootstrap engine components, and bounded transfer exercises.
- Missing: one canonical live work object traversing every state with independent verification and baseline update.
- Official when: the monorepo records one complete loop with immutable artifacts and a destination adoption or rejection receipt.

### SAN-008: The network has an open-source portable kernel

- Status: **built privately, not released**
- Evidence: private monorepo PR #1 with schemas, protocols, validators, capability draft, and corpus projection.
- Missing: review, merge, active CI, CodeRabbit, branch controls, license, public release, installation documentation, and external clean-room use.
- Official when: a tagged public release passes CI and a non-author clean-room install.

### SAN-009: The public website represents a real operating network

- Status: **partially true**
- Evidence: live verified website, live four-agent Discord, bounded bootstrap and transfer pilots.
- Limit: the frontier, public registry, intake, and compounding baseline are not yet operating products.
- Public wording rule: describe these as the model and roadmap until the corresponding claims above become official.

## Claims rule

A later claim status must cite an immutable artifact or receipt, exact version, test conditions, result, evidence boundary, and rollback state. Conversation, architecture prose, a PR, or one passing demo cannot advance a claim to `operating`.
