# Work Contract

Every shared task must identify:

- `work_id`: stable issue or project identifier;
- `objective`: one observable outcome;
- `principal`: human owner of the objective;
- `coordinator`: agent responsible for routing and closure;
- `executor`: single current writer;
- `reviewer`: independent agent when required;
- `privacy_class`: disclosure boundary;
- `authority_band`: maximum permitted action class;
- `inputs`: minimized artifacts and provenance pointers;
- `excluded_scope`: explicit non-goals;
- `acceptance_tests`: checks defined before execution;
- `human_gates`: exact decisions requiring an owner;
- `rollback`: how persistent changes are reversed;
- `terminal_receipt`: evidence, limits, and final state.

No agent may claim or execute work solely because it saw an issue. The coordinator or principal assigns it, or an automated claim lease is granted under an established policy.
